## Review (required by the handoff: "Do not install Drizzle 0023 without separate review and approval")

**Conflicts checked**
- **Security 0031:** no policy is created or altered; the new table has no policies. md5 checked before and after.
- **S1 (`zz_application_write_guard` on `applications`):** 0023 never writes `applications` (backfill reads it; `reserve` takes a row lock `FOR UPDATE` but updates nothing). The new FK to `applications(id)` adds internal RI triggers on `applications`; the package fingerprint excludes internal triggers, as S1-era packages do. **Open item:** the S1 package source is not in the repo, so run S1's own `verify-after-readonly.sql` after install to confirm `all_gates: true`.
- **Payment guards:** `payments` is not touched (fingerprint + row count checked).
- **Dependencies:** `applications` (id, email, full_name, deleted_at, purged_at, resubmission_history), `application_resume_tokens` (incl. revoked_at), `application_identity_reviews` (0019/0020 columns), `user_roles`, `audit_log`, `private.is_manager()`, `auth.role()`, `auth.uid()`, `auth.users`. All are checked by the preflight and again inside the package; it refuses with `AR23_DEPENDENCY_MISSING` otherwise. Production already confirmed `application_resume_tokens` exists.

**Risks**
1. **No Drizzle receipt is written** (same rule as the other packages). The repo journal lists 0023, so an automatic `drizzle migrate` would try to re-run it and fail on `CREATE TABLE` (harmless refusal, but noisy). Nothing in the build runs migrations automatically today.
2. **Brief write lock on `applications`** (SHARE ROW EXCLUSIVE, at most seconds; applicant saves wait or fail with lock_timeout 5 s). Install in a quiet window.
3. **Backfill reads every applicant's `resubmission_history`** inside the transaction; it inserts only attempt rows (no email, no token). Preflight reports how many applicants have link history.
4. **App coupling:** the code calls these RPCs only when env `APPLICATION_RESUME_ATOMIC_ENABLED=true` (`src/lib/application-recovery.server.ts`, `identity-review.functions.ts`). Installing is inert until then. **Never set that env var before install, and unset it before any rollback.** `APPLICATION_RESUME_ENABLED` (hard false) is separate.
5. **`resolve_application_identity_review` is callable by every authenticated user** (as designed); it refuses non-managers inside via `private.is_manager()` and an `admin`/`team` role in `user_roles`. Preflight lists the role values in use.
6. **Supabase default privileges:** service_role may also get DELETE/TRUNCATE/REFERENCES/TRIGGER on the new table from `ALTER DEFAULT PRIVILEGES`; not reachable for anon/authenticated (checked).
7. **Rollback** drops the attempts table (rate-limit history only); recovery tokens already issued stay in `application_resume_tokens` and expire in 30 minutes.
8. **Local test used a stand-in schema**, not `rr_tpl`. A production-order baseline run (like `payments-guards-preservation.db.test.mjs`) is recommended before approval.
