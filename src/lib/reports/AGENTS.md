- Vehicle Profitability: owners and managers only, and only while VEHICLE_PROFITABILITY_ENABLED is true (a constant, default false). getVehicleProfitReport throws before requireManager and before any payment, rental, expense, or maintenance read while it is false; the tab is omitted and a direct link falls back to Overview. With the flag on, one row per vehicle covers a chosen Eastern Time date range, defaulting to the last 90 days. Collected revenue is a paid or refunded payment net of refunds, attributed through the rental's vehicle. A payment with no vehicle is listed and is not given one. Deposits are excluded. Expenses are vehicle_expenses.amount. Maintenance is company_share, or total_cost when the share is blank, and a service that already has an in-range expense is counted once. Net, days rented against days the vehicle existed in the range, utilization, and revenue per rented day are shown with cents. Depreciation is not a vehicle column, and acquisition, lender, and payoff are owner finance and are not read. CSV is built in the browser. No Stripe, no writes, and no SQL.
- Owner Expense Entry: owners only, and only while OWNER_EXPENSE_ENTRY_ENABLED is true (a constant, default false). createOwnerExpense and listOwnerExpenseChoices throw before the role lookup and before any read or write while it is false; the tab and its save button are omitted. One insert into vehicle_expenses goes through the signed-in client, so the existing "Managers manage vehicle expenses" policy (private.is_manager(), which includes Owner) still applies. Amount must be greater than zero. The vehicle must exist. Category is the existing check constraint. Description is required because that column is NOT NULL. An optional receipt uses the existing receipts bucket and FileUploader. No edit, no delete, no service role, and no audit_log write — authenticated has no INSERT grant on audit_log.
- Accountant Year-to-Date Export: owners only, and only while ACCOUNTANT_EXPORT_ENABLED is true (a constant, default false). getAccountantExport returns disabled before the owner check and before any table or Stripe read while it is false; a direct link falls back to Overview and the tab is omitted. The screen is one Eastern Time calendar year. Each month is buildOwnerPnlMonth, and charges come from one readLivePartnerCharges call for that year (no second Stripe list). The Stripe page cap and the Owner P&L directory page cap stay as they are; a hit is a visible warning and the totals that depend on the capped read are blank. Unattributed charges and deposits stay off the net. Stripe fees are the same read-only balance transactions as Monthly Owner P&L, one Eastern Time month at a time, and they are subtracted from net. A failed or truncated fee read shows Fees as Unavailable and that net as Partial. Two CSVs are built in the browser: the monthly summary, and an expense detail whose receipt column is Yes or No with no receipt URL. No writes, no SQL, and no email.
- Stripe Payout Breakdown: owners only, and only while PAYOUT_BREAKDOWN_ENABLED is true (a constant, default false). getPayoutBreakdown returns disabled before the owner check and before any Stripe or table read while it is false; a direct link falls back to Overview and the tab is omitted. The range is Eastern Time on payout.created. Each payout's balance transactions are grouped into charges, refunds, Stripe fees, disputes or adjustments, and other, and a row is flagged when those parts do not sum to the payout. Charges are matched with matchStripeCustomers. The reader is createReadOnlyStripe with the cache on, list and retrieve only, and the shared 100-page cap. A cap is a visible warning and the totals that depend on it are not shown as complete. CSV is built in the browser. No writes, no SQL, and no email.
- Billing Health: owners only, off while BILLING_HEALTH_ENABLED is false. getBillingHealth returns disabled before the owner check and before any Stripe or rental read. With the flag on it compares active rentals (status, weekly_rate, next_payment_due, stripe_customer_id, stripe_subscription_id) to Stripe subscriptions.list and customers.retrieve through the shared reader with the cache opted in. Mismatches are display only. A 100-page cap shows a warning and no partial result. The screen never fixes a rental, writes Stripe, or sends email.
- Revenue Forecast: owners only, off while REVENUE_FORECAST_ENABLED is false. getRevenueForecast returns disabled before the owner check and before any read. With the flag on it projects the next 4 Monday–Sunday Eastern Time weeks from active rentals (weekly_rate on next_payment_due, then every 7 days, stopping after rentals.end_date). A missing next_payment_due is excluded and counted. Idle vehicles are in fleet with no active rental; potential weekly income uses vehicles.weekly_rate and is not added to the projection. The screen is a projection, not collected money. No Stripe, no writes, no emails.
- Receivables Aging: RECEIVABLES_AGING_ENABLED is a hard constant, false. While it is false the admin tab is absent, a direct link falls back to Overview, and getReceivablesAging throws before requireManager and before any read. With the flag on, owners and managers get a read-only aging of open rent payments on active rentals and rentals ended within 30 days (Eastern Time). Amount owed uses amount minus net_collected when both are set. Deposits are excluded. A page cap withholds totals. No writes and no Stripe calls. There is no drivers table; the driver is applications.full_name.
